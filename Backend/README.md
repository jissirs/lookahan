# lookahan Backend (Flask)

ระบบหลังบ้านของแอปจัดการ stock วัตถุดิบ เมนู และออเดอร์ร้านอาหาร พร้อม AI (Groq) พยากรณ์ยอดขายของวันพรุ่งนี้
คู่มือร้านเดียวและ deployment ล่าสุด: [PRODUCTION.md](../PRODUCTION.md)
เขียนด้วย Python + Flask ให้ **อ่านง่าย เหมาะกับใช้สอน**: ไม่มีชั้นซ้อนหลายชั้น ไฟล์แต่ละไฟล์ทำงานครบในตัว และมีคอมเมนต์ภาษาไทยทุกจุดสำคัญ

> ฐานข้อมูลใหม่เริ่มว่าง: โหมดพัฒนาสมัครคนแรกเป็นเจ้าของร้านได้ ส่วน production สร้างเจ้าของผ่าน `flask --app wsgi bootstrap-owner` ผู้สมัครภายหลังต้องรออนุมัติ ไม่ seed ข้อมูลตัวอย่างอัตโนมัติ
> ลำดับการเปิด: **รัน Backend ก่อน** แล้วค่อย `npm run dev` ที่ `frontend/`

## 1. ติดตั้งและรัน (ทำตามทีละขั้น)

### สิ่งที่ต้องมีก่อน
- **Python 3.10 ขึ้นไป** (ตรวจด้วย `python --version`) — ดาวน์โหลดที่ https://www.python.org/downloads/ และติ๊ก "Add Python to PATH" ตอนติดตั้ง
- ไม่ต้องติดตั้งฐานข้อมูลก่อน: ค่าเริ่มต้นใช้ **SQLite** (ไฟล์ในเครื่อง) ถ้าอยากใช้ MySQL ออนไลน์ ดู[ข้อ 3](#3-ใช้ฐานข้อมูล-mysql-ออนไลน์)
- (ไม่บังคับ) คีย์ของ Groq ถ้าอยากใช้ AI พยากรณ์ ดู[ข้อ 4](#4-ตั้งค่า-ai-groq)

### ขั้นที่ 1: เข้าโฟลเดอร์ Backend
```bash
cd Backend
```

### ขั้นที่ 2: สร้างสภาพแวดล้อมเสมือน (virtual environment)
venv คือ "กล่องแยก" สำหรับเก็บไลบรารีของโปรเจกต์นี้ ไม่ให้ปนกับโปรเจกต์อื่น ทำครั้งเดียว
```bash
python -m venv venv
```

### ขั้นที่ 3: เปิดใช้งาน venv (ต้องทำทุกครั้งที่เปิดเทอร์มินัลใหม่)

| เทอร์มินัล | คำสั่ง |
|---|---|
| PowerShell (Windows) | `venv\Scripts\Activate.ps1` |
| Command Prompt (Windows) | `venv\Scripts\activate.bat` |
| Git Bash (Windows) | `source venv/Scripts/activate` |
| macOS / Linux | `source venv/bin/activate` |

สำเร็จเมื่อหน้าบรรทัดคำสั่งมี `(venv)` นำหน้า

### ขั้นที่ 4: ติดตั้งไลบรารี
```bash
pip install -r requirements.txt
```

### ขั้นที่ 5: สร้างไฟล์ตั้งค่า `.env`
คัดลอกไฟล์ตัวอย่าง (ไฟล์ `.env` จะไม่ถูกอัปโหลดขึ้น git เพราะมีรหัสลับ)
```bash
# Windows (PowerShell / CMD)
copy .env.example .env
# Git Bash / macOS / Linux
cp .env.example .env
```
ถ้าจะลองบนเครื่องเฉย ๆ **ไม่ต้องแก้อะไรเลย** ใช้ SQLite ได้ทันที (แต่ก่อนใช้งานจริงให้เปลี่ยน `SECRET_KEY` เป็นข้อความสุ่มยาว ๆ)
ตัวแปรทั้งหมดอธิบายไว้ใน[ข้อ 2](#2-ไฟล์ตั้งค่า-env-ตัวแปรทั้งหมด)

### ขั้นที่ 6: สร้างตาราง
```bash
flask --app wsgi init-db
```
สร้างตารางที่ยังไม่มี (ปลอดภัย รันซ้ำได้ ไม่แตะข้อมูลเดิม) ฐานข้อมูลจะ **ว่างเปล่า** — ไม่มีบัญชีหรือข้อมูลตัวอย่าง

### ขั้นที่ 7: รันเซิร์ฟเวอร์
```bash
flask --app wsgi run
```
เซิร์ฟเวอร์เปิดที่ **http://127.0.0.1:5000** (หยุดด้วย `Ctrl + C`)

> `flask run` **ไม่โหลดโค้ดหรือ `.env` ใหม่เอง** — แก้ไฟล์แล้วต้องหยุดแล้วรันใหม่ (หรือรันด้วย `flask --app wsgi run --debug` ระหว่างพัฒนา จะรีสตาร์ทให้เมื่อแก้โค้ด)

### ขั้นที่ 8: ตรวจว่าทำงาน
เปิดเบราว์เซอร์ไปที่ http://127.0.0.1:5000/api/v1/health ต้องเห็น
```json
{"database": "ok", "status": "ok"}
```
จากนั้นเปิดหน้าเว็บ (`cd ../frontend` → `npm run dev` → http://localhost:5173) สมัครผู้ใช้คนแรกที่หน้า Register แล้วเพิ่มวัตถุดิบ เมนู และออเดอร์ตามปกติ

> **สรุปแบบสั้น** (เมื่อติดตั้งครบแล้ว ครั้งต่อไปใช้แค่นี้):
> `cd Backend` → เปิด venv → `flask --app wsgi run`

## 2. ไฟล์ตั้งค่า `.env` (ตัวแปรทั้งหมด)

ไฟล์ `Backend/.env` (คัดลอกจาก `.env.example`) — **เป็นความลับ ห้ามอัปโหลดขึ้น GitHub หรือส่งให้ใคร** (ถูกกันไว้ใน `.gitignore` แล้ว)

| ตัวแปร | ต้องมี? | ความหมาย | ตัวอย่าง |
|---|---|---|---|
| `DATABASE_URL` | ไม่ | ที่อยู่ฐานข้อมูล เว้นว่าง = ใช้ SQLite (`instance/dev.db`) | `mysql+pymysql://user:pass@host:14008/defaultdb` |
| `DB_SSL_CA` | ถ้าฐานข้อมูลบังคับ SSL | path ของไฟล์ CA certificate (`.pem`) ใช้ `/` ไม่ใช้ `\` | `C:/Users/me/aiven-ca.pem` |
| `SECRET_KEY` | ใช่ (ก่อนใช้จริง) | ข้อความสุ่มยาว ๆ ของระบบ | (สุ่มเอง) |
| `CORS_ORIGINS` | ไม่ | ที่อยู่หน้าเว็บที่อนุญาตให้เรียก API (คั่นด้วย `,`) | `http://localhost:5173` |
| `GROQ_API_KEY` | ถ้าจะใช้ AI | คีย์ของ Groq | `gsk_...` |
| `SMTP_HOST` | ถ้าจะส่งอีเมลจริง | เซิร์ฟเวอร์อีเมล เว้นว่าง = ยังไม่ส่งอีเมลจริง (โหมดทดลอง) — ต้องกรอกคู่กับ `SMTP_USER` และ `SMTP_PASSWORD` | `smtp.gmail.com` |
| `SMTP_PORT` | ไม่ | พอร์ต (587 = starttls, 465 = ssl) ค่าเริ่มต้น 587 | `587` |
| `SMTP_USER` | ถ้าจะส่งอีเมลจริง | บัญชีอีเมลที่ใช้ส่ง | `me@gmail.com` |
| `SMTP_PASSWORD` | ถ้าจะส่งอีเมลจริง | Gmail ใช้ "รหัสผ่านแอป" 16 ตัว (ไม่ใช่รหัสผ่านปกติ) | `abcd efgh ijkl mnop` |
| `SMTP_FROM` | ไม่ | ที่อยู่ผู้ส่งที่ผู้รับเห็น ค่าเริ่มต้น = `SMTP_USER` | `lookahan <me@gmail.com>` |
| `SMTP_SECURITY` | ไม่ | `ssl` / `starttls` / `none` (none = เซิร์ฟเวอร์ทดสอบในเครื่องเท่านั้น) ค่าเริ่มต้นเลือกตามพอร์ต | `starttls` |
| `GROQ_MODEL` | ไม่ | โมเดลที่ใช้ เว้นว่าง = `openai/gpt-oss-120b` | `openai/gpt-oss-20b` |
| `APP_ENV` | ตอน deploy | ตั้งเป็น `production` เพื่อห้ามตอบ OTP กลับในคำตอบ (ต้องตั้งค่าอีเมลก่อน) และปิดคำสั่ง `reset-db` | `production` |

กฎการเขียน `.env` (พลาดบ่อย):
- **หนึ่งบรรทัด = หนึ่งตัวแปร ค่าอยู่หลัง `=` บรรทัดเดียว** — ห้ามเขียนคอมเมนต์ต่อท้ายบรรทัดเดียวกัน (ระบบจะอ่านทั้งบรรทัดเป็นค่าว่างแล้วข้ามไปใช้ค่าเริ่มต้นโดยไม่แจ้ง) ถ้าต้องการคอมเมนต์ ให้ขึ้นบรรทัดใหม่ที่ขึ้นต้นด้วย `#`
- ไม่ต้องใส่เครื่องหมายคำพูดรอบค่า และไม่ต้องมีช่องว่างรอบ `=`
- **อย่าใส่ตัวแปรชื่อเดียวกันซ้ำ** ระบบจะใช้ตัวหลังสุดโดยไม่บอก
- แก้ `.env` แล้วต้องหยุดแล้วรันเซิร์ฟเวอร์ใหม่

## 3. ใช้ฐานข้อมูล MySQL ออนไลน์

ถ้าไม่ใส่ `DATABASE_URL` ระบบใช้ SQLite — เหมาะกับทดลองคนเดียว ถ้าทีมต้องใช้ฐานข้อมูลร่วมกันหรือจะ deploy ให้ใช้ MySQL ออนไลน์

ข้อกำหนดของฐานข้อมูล: **MySQL 8.0.16 ขึ้นไป** (หรือ MariaDB 10.2.1+) เพราะระบบใช้กฎ `CHECK` ในตาราง (เช่น stock ห้ามติดลบ)

### ขั้นที่ 1: สมัครและสร้างฐานข้อมูล
ตัวอย่างที่ใช้ได้ (สมัครเอง — เงื่อนไขแพ็กเกจฟรีเปลี่ยนได้ ตรวจที่เว็บของเขา): **Aiven for MySQL** (มีแพ็กเกจ Free) ที่ https://aiven.io/free-mysql-database
1. สมัครสมาชิก → สร้างบริการ **MySQL** → เลือกแพ็กเกจ **Free** → รอสถานะ **Running**
2. เปิดหน้า **Connect** ของบริการ จะเห็นข้อมูลเชื่อมต่อ: **Host, Port, User, Password, Database name** (ค่าเริ่มต้นของ Aiven: user `avnadmin`, database `defaultdb` ใช้ชื่อนี้ได้เลยไม่ต้องสร้างใหม่)
3. หน้า **Overview** ของบริการ กด **Download** ที่ช่อง **CA certificate** ได้ไฟล์ `ca.pem` เก็บไว้ในเครื่อง (แนะนำเก็บนอกโฟลเดอร์โปรเจกต์ เช่น `C:\Users\<ชื่อ>\aiven-ca.pem`)
4. ถ้าผู้ให้บริการมี allow list / firewall อย่าลืมอนุญาต IP ของเครื่องคุณ

ผู้ให้บริการอื่นก็ใช้วิธีเดียวกัน (ต้องการ 5 ค่า + CA certificate ถ้าเขาบังคับ SSL)

### ขั้นที่ 2: ใส่ในไฟล์ `.env`
```env
DATABASE_URL=mysql+pymysql://USER:PASSWORD@HOST:PORT/DATABASE
DB_SSL_CA=C:/Users/me/aiven-ca.pem
```
แทน `USER`, `PASSWORD`, `HOST`, `PORT`, `DATABASE` ด้วยค่าจากขั้นที่ 1
- **รหัสผ่านมีอักขระพิเศษ** ต้องแปลงเป็นรหัส URL: `@` → `%40`, `/` → `%2F`, `#` → `%23`, `:` → `%3A`
- ระบบเติม `?charset=utf8mb4` ให้เอง (จำเป็นสำหรับภาษาไทย) ไม่ต้องใส่
- ต้องมี `DB_SSL_CA` ถ้าผู้ให้บริการบังคับ SSL (Aiven บังคับ)

### ขั้นที่ 3: ทดสอบการเชื่อมต่อ (อ่านอย่างเดียว ไม่แก้อะไร)
```bash
flask --app wsgi check-db
```
สำเร็จจะเห็น `เชื่อมต่อสำเร็จ — เวอร์ชันฐานข้อมูล: 8.x.x` และชุดตัวอักษร ถ้าไม่สำเร็จจะบอกสาเหตุและวิธีแก้ที่พบบ่อย (รหัสผ่านผิด, ยังไม่มีฐานข้อมูล, ปัญหา SSL, firewall)

### ขั้นที่ 4: สร้างตาราง แล้วรันตามปกติ
```bash
flask --app wsgi init-db
flask --app wsgi run
```

ข้อควรระวัง:
- `reset-db` จะลบทุกตารางในฐานข้อมูลนั้น **อย่ารันกับฐานข้อมูลที่มีข้อมูลจริง**
- ถ้าเซิร์ฟเวอร์เก่ายังเปิดค้างที่พอร์ต 5000 คำขอจะไปเข้าตัวเก่า (ใช้ฐานข้อมูลและโค้ดเก่า) — ปิดตัวเก่าก่อนเสมอ (`Ctrl + C` ที่เทอร์มินัลเดิม)
- ก่อน deploy จริง: ตั้ง `APP_ENV=production` และเปลี่ยน `SECRET_KEY`

## 4. ตั้งค่า AI (Groq)

AI ในระบบมี **8 หน้าที่** — ผลถูกบันทึกในตาราง `forecasts` (ชุดล่าสุด) และ `forecast_history` (ผลของแต่ละวัน ไว้วัดความแม่น) แสดงที่หน้า Home / Statistics / Ai / กระดิ่งแจ้งเตือน

| # | หน้าที่ของ AI | ใครทำส่วนไหน |
|---|---|---|
| 1 | พยากรณ์ออเดอร์รายชั่วโมงของพรุ่งนี้ | AI คาดการณ์ → **โค้ด** รวมเลขและหาช่วงเยอะสุดเอง |
| 2 | คาดเมนูขายดีที่สุด | AI เลือก → โค้ดตรวจว่าเป็นเมนูที่เปิดขายจริง |
| 3 | เช็กจำนวนรายการวัตถุดิบที่มี | **โค้ดนับ** (ทั้งหมด/ปกติ/ใกล้หมด/วิกฤต/ตามหมวด) → AI เขียนสรุปสถานะเป็นประโยค |
| 4 | แจ้งเตือนวัตถุดิบใกล้หมด และเมนูที่วัตถุดิบไม่พอทำ | AI เลือกเรื่องและเขียนข้อความ → โค้ดตรวจกับ stock จริงก่อน แล้วสร้างแจ้งเตือนที่กระดิ่ง |
| 5 | พยากรณ์รายได้ (และออเดอร์) รายวัน 7 วันข้างหน้า | AI คาดการณ์ → โค้ดตรวจความสมเหตุสมผลกับราคาเฉลี่ยต่อออเดอร์ |
| 6 | เขียนคำแนะนำภาษาไทย 3–4 ข้อ | AI เขียน |
| 7 | คาดสัดส่วนประเภทเมนู | AI คาดการณ์ → โค้ดปรับให้รวมเป็น 1 |
| 8 | เสนอ "เมนูพิเศษ" จากวัตถุดิบที่คาดว่าจะเหลือค้างคืน | AI คิดเมนู → **โค้ด**ตรวจว่าวัตถุดิบมีจริง ปริมาณไม่เกิน stock ใช้ของที่เหลืออย่างน้อย 1 อย่าง และคิดต้นทุน/กันราคาต่ำกว่าทุนเอง (ราคา ≥ ต้นทุน × 1.3) |

### AI เรียนรู้จากผลจริง และถูกวัดผล

เป้าหมาย "ของค้างคืนน้อยที่สุด" จะรู้ว่าทำได้จริงไหมก็ต้องวัด ระบบจึงมี 2 วงจร:

1. **วัดความแม่นของพยากรณ์** (`forecast_history`)
   - ทุกครั้งที่วิเคราะห์ โค้ดเก็บผลพยากรณ์ของ "พรุ่งนี้" (ออเดอร์ รายได้ ค่าอ้างอิงจากสถิติธรรมดา และของค้างที่แผนคาดไว้) — วิเคราะห์ซ้ำวันเดียวกันทับของเดิม
   - เมื่อวันนั้นผ่านไป โค้ดเติม **ยอดจริง** ให้เองเมื่อมีคนเรียก `GET /ai/accuracy` หรือสั่งวิเคราะห์ครั้งต่อไป (`fill_actuals`)
   - `GET /ai/accuracy` ให้ค่าคลาดเฉลี่ย (MAPE), ความเอนเอียง (บวก = พยากรณ์สูงเกิน) และ **AI แม่นกว่าสถิติธรรมดา (ค่าเฉลี่ยของวันเดียวกันในสัปดาห์) ไหม** (ตัดสินเมื่อมีข้อมูล ≥ 3 วัน)
   - ผลครั้งก่อน ๆ ถูกส่งให้ AI ด้วย (`lastForecastResults`, `forecastAccuracy`, `baselineOrders`) และ prompt สั่งให้ปรับตัว: คลาดสูงต่อเนื่องให้ลด คลาดต่ำให้เพิ่ม

2. **ปิดร้านทุกคืน** (`closing_counts`, `closing_lines` — หน้า `/closing`)
   - นับวัตถุดิบที่เหลือจริง + จดของเสีย → ได้ **มูลค่าของค้างคืน / ของเสีย / ส่วนต่างจากที่ระบบคิด** เป็นตัวเลขจริง
   - ระบบปรับ stock ให้เท่าที่นับจริง บันทึกประวัติ `Drop` "ของเสีย (ปิดร้าน)" และ `Add`/`Drop` "ปรับตามที่นับจริง (ปิดร้าน)"
   - วันละครั้ง ปิดแล้วแก้ไม่ได้ (ตัวเลขจึงเชื่อถือได้) — ผลล่าสุดถูกส่งให้ AI (`closingResults`) และแสดงที่ส่วน "ความสดของวัตถุดิบ" ของหน้า Ai เทียบกับที่แผนคาดไว้

### เป้าหมายด้านความสด: ใช้วัตถุดิบให้หมดพอดี ของค้างคืนน้อยที่สุด

โค้ดคำนวณ "แผนความสด" (`build_outlook` ใน `app/forecast.py`) จากผลพยากรณ์ × สูตรเมนู เทียบกับ stock จริง แล้วเก็บไว้ในผลพยากรณ์ (`outlook`):
- **ควรเติม**: วัตถุดิบที่คาดว่าไม่พอ → เติม **เท่าที่ขาดพอดี** (ปัดขึ้นตามขั้นของปุ่ม +/−) ไม่เติมเผื่อ เพื่อไม่ให้เหลือค้างคืน
- **เหลือค้างคืน**: วัตถุดิบที่ stock มากกว่าที่คาดว่าจะใช้ → ไม่ต้องเติม และแนะนำ **เมนูที่ควรโปรโมต** เพื่อใช้ให้หมด พร้อมมูลค่าที่คาดว่าจะค้าง (บาท และเปอร์เซ็นต์ของมูลค่า stock ที่เกี่ยวกับเมนู — ยิ่งน้อยยิ่งดี)
- วิธีคำนวณ: จานที่คาดว่าจะขาย = ออเดอร์ที่คาด × จานต่อออเดอร์ (จากประวัติ) × สัดส่วนประเภท แล้วแบ่งให้แต่ละเมนูตามยอดขายในอดีต (เมนูที่ไม่เคยขายแบ่งเท่า ๆ กัน) แล้วคูณสูตรเมนู — นับเฉพาะวัตถุดิบที่อยู่ในสูตรของเมนูที่เปิดขาย
- ส่วนนี้ส่งให้ AI ด้วย (ค่าฐานจากยอดเฉลี่ยต่อวัน) เพื่อให้คำแนะนำพูดถึงการใช้ของให้หมด และ prompt สั่ง AI ว่าห้ามแนะนำให้ซื้อเผื่อเกิน
- หน้าเว็บใช้ตัวเลขชุดเดียวกันนี้ทั้งส่วน "ความสดของวัตถุดิบ" และ "คำแนะนำให้เติม" (ไม่คำนวณซ้ำให้ตัวเลขสองชุดขัดกัน)

### การแจ้งเตือนจาก AI (หน้าที่ 4)

- AI เลือกได้เฉพาะ: วัตถุดิบที่ **ใกล้หมด/วิกฤต หรือคาดว่าไม่พอพรุ่งนี้**, และเมนูที่ **ตอนนี้วัตถุดิบไม่พอทำจริง** (โค้ดคำนวณส่วนที่ขาดเอง) เรื่องที่ AI แต่งขึ้นหรือไม่ตรงกับ stock จริงจะถูกทิ้ง ระดับความสำคัญ (เหลือง/แดง) และตัวเลขรายละเอียดโค้ดเป็นคนกำหนด
- แจ้งที่กระดิ่งด้วยหัวข้อขึ้นต้น "AI เตือน: …" และ **ไม่แจ้งซ้ำเรื่องเดิมภายใน 24 ชั่วโมง** (วิเคราะห์ใหม่ทุก 6 ชั่วโมงก็ไม่เด้งซ้ำ) ใช้ประเภทแจ้งเตือน `stock_low`/`stock_critical` ที่มีอยู่แล้ว จึงไม่ต้องแก้โครงตารางฐานข้อมูล
- แจ้งเตือนแบบกฎ (ตอน stock ข้ามเกณฑ์ ทันทีที่เพิ่ม/ลด) ยังทำงานเหมือนเดิม — AI เป็นตัวเสริมที่เห็นภาพรวมและคาดการณ์ล่วงหน้า

### ผลที่ AI วิเคราะห์ได้ (ฟิลด์ใน `POST /ai/forecast` และ `forecast` ของ `GET /dashboard/summary`)

`orders`, `peakStart`, `peakEnd`, `bestSeller`, `hourly[]`, `categories[]`, **`revenue`** (รายได้พรุ่งนี้, บาท), **`avgOrderValue`**, **`daily[]`** (7 วัน: `date`, `weekday`, `orders`, `revenue`), **`inventory`** (`total`, `normal`, `low`, `critical`, `out_of_stock`, `byCategory`, `check` = ประโยคสรุปของ AI), **`alerts[]`** (`type`, `name`, `level`, `title`, `message`, `detail`, `link`), **`outlook`** (แผนความสด), **`specials[]`** (เมนูพิเศษ: `name`, `description`, `category`, `price`, `cost`, `ingredients[]`, `uses[]`), `advice[]`, `source`, `generatedAt`

### ตั้งค่า
1. สมัครและสร้างคีย์ที่ https://console.groq.com/keys
2. ใส่ใน `.env` บรรทัดเดียว: `GROQ_API_KEY=gsk_...`
3. (ไม่บังคับ) เปลี่ยนโมเดลด้วย `GROQ_MODEL=` ดูรายชื่อที่คีย์ของคุณใช้ได้ที่ https://console.groq.com/docs/models — ค่าเริ่มต้น `openai/gpt-oss-120b` (ถ้าโมเดลถูกถอดออก จะได้ error `Groq ตอบผิดพลาด (404)` ให้เปลี่ยนเป็นโมเดลที่ยังมี)
4. รันเซิร์ฟเวอร์ใหม่

**คีย์เป็นความลับ** — เก็บใน `.env` ของ Backend เท่านั้น ห้ามใส่ในโค้ด ในหน้าเว็บ หรือส่งขึ้น GitHub ถ้าเผลอเปิดเผยให้สร้างคีย์ใหม่ที่ console.groq.com/keys แล้วลบอันเก่า

### AI ทำงานเมื่อไร
- **อัตโนมัติ**: เมื่อเปิดหน้า Home / Statistics / Ai ถ้ายังไม่มีผลพยากรณ์ หรือผลเก่ากว่า **6 ชั่วโมง** หน้าเว็บจะเรียก `POST /ai/forecast` ให้เองเบื้องหลัง (ถ้าล้มเหลวจะรอ 10 นาทีค่อยลองใหม่ ไม่เรียกรัว ๆ)
- **สั่งเอง**: ปุ่ม "ให้ AI วิเคราะห์ใหม่" ที่หน้า Ai
- ต้องมีออเดอร์ในระบบอย่างน้อย 1 ใบ ถึงจะวิเคราะห์ได้ (ข้อมูลน้อยผลจะคลาดเคลื่อน และ AI จะแจ้งเตือนในคำแนะนำ)

### แบ่งงานระหว่าง AI กับโค้ด
- **AI** คาดการณ์ เลือกเรื่องที่ควรเตือน และเขียนข้อความภาษาคน
- **โค้ด** (`app/forecast.py`) เตรียมข้อมูล ทำเลขทั้งหมดเอง (รวมออเดอร์, หาช่วงเยอะสุด, นับวัตถุดิบ, แผนความสด) และ **ตรวจคำตอบของ AI ทุกครั้ง** (`clean_forecast`, `clean_alerts`): ตัดประเภท/เมนู/วัตถุดิบที่ไม่มีจริง ปรับสัดส่วนให้รวมเป็น 1 แก้รายได้ที่เกินจริง ตรวจการแจ้งเตือนกับ stock จริง ถ้าคำตอบใช้ไม่ได้จะแจ้ง `AI_ERROR`
- ส่งให้ AI เฉพาะ "ตัวเลขสรุป" ของร้าน (ไม่ส่งชื่อ/อีเมลผู้ใช้)
- ไม่ให้ AI คิดเลขที่ต้องแม่น (จำนวนที่ควรเติม, ของค้างคืน, นับวัตถุดิบ) — โค้ดคำนวณแล้วให้ AI ใช้เขียนคำแนะนำ

### ปรับแต่ง AI
- **ข้อความสั่ง AI (system prompt)**: แก้ที่ [app/prompts.py](app/prompts.py) ไฟล์เดียว (บทบาท กติกา รูปแบบ JSON) ถ้าเปลี่ยนรูปแบบ JSON ต้องแก้ `clean_forecast()` ใน `app/forecast.py` ให้ตรงกันด้วย
- **ช่วงเวลาที่ให้ AI ดู / ชั่วโมงเปิดร้าน / จำนวนวันที่พยากรณ์รายได้ / จำนวนเรื่องที่ AI เตือนได้**: `HISTORY_DAYS`, `OPEN_HOURS`, `FORECAST_DAYS`, `MAX_ALERTS` ใน `app/forecast.py`
- **ตัวเรียก Groq**: ฟังก์ชัน `ask_groq` ท้ายไฟล์ `routes/ai.py` (timeout 30 วินาที, บังคับตอบเป็น JSON)

## 5. ตั้งค่าอีเมล (ส่ง OTP จริง)

ผู้ใช้กด "forget password" แล้วระบบส่งรหัส OTP 6 หลักไปที่อีเมลของเขา (หมดอายุใน 5 นาที ใช้ได้ครั้งเดียว กรอกผิดได้ 5 ครั้ง ขอใหม่ได้ทุก 60 วินาที)
ระบบส่งอีเมลผ่าน **SMTP** (ไม่ต้องติดตั้งไลบรารีเพิ่ม) ใช้ได้กับผู้ให้บริการอีเมลทุกเจ้าที่ให้ค่า SMTP ด้านล่างคือตัวอย่างกับ **Gmail** (ฟรี ส่งได้ประมาณ 500 ฉบับ/วัน เหมาะกับโปรเจกต์เล็ก)

### ขั้นที่ 1: สร้าง "รหัสผ่านแอป" ของ Gmail
Gmail ไม่ให้โปรแกรมอื่นใช้รหัสผ่านปกติ ต้องสร้างรหัสผ่านแอปแยกต่างหาก:
1. เปิด **การยืนยันแบบ 2 ขั้นตอน** (2-Step Verification) ที่ https://myaccount.google.com/security (ต้องเปิดก่อน ไม่งั้นจะไม่มีเมนูรหัสผ่านแอป)
2. ไปที่ https://myaccount.google.com/apppasswords ตั้งชื่อแอปเช่น `lookahan` แล้วกด **สร้าง**
3. จะได้รหัส 16 ตัวอักษร (แสดงแบบมีช่องว่างเป็นกลุ่ม ๆ) — **คัดลอกเก็บไว้ทันที** ปิดหน้าแล้วดูอีกไม่ได้ (ถ้าลืมให้สร้างใหม่)

### ขั้นที่ 2: ใส่ในไฟล์ `.env`
```env
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=อีเมลของคุณ@gmail.com
SMTP_PASSWORD=รหัสผ่านแอป16ตัว
SMTP_FROM=อีเมลของคุณ@gmail.com
```
- ใส่รหัสผ่านแอปติดกันหรือมีช่องว่างก็ได้ (ระบบตัดช่องว่างให้เอง) ไม่ต้องใส่เครื่องหมายคำพูด
- `SMTP_FROM` ของ Gmail ต้องเป็นอีเมลเดียวกับ `SMTP_USER` (Gmail ไม่ให้ใช้ชื่อผู้ส่งอื่นปลอมตัว) ใส่ชื่อแสดงได้ เช่น `lookahan <อีเมลของคุณ@gmail.com>`
- ใช้ผู้ให้บริการอื่นได้ (เช่น Brevo, Mailgun, SendGrid, Resend ที่มี SMTP) แค่เปลี่ยน `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD` ตามที่เขาให้ ถ้าเขาใช้พอร์ต 465 จะใช้ `ssl` ให้เอง
- เขียนค่าบรรทัดเดียว ห้ามมีคอมเมนต์ต่อท้ายบรรทัดเดียวกัน (เหมือนตัวแปรอื่น)
- **ต้องกรอกครบทั้ง `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD`** ระบบถึงจะเริ่มส่งอีเมลจริง ถ้ากรอกครึ่ง ๆ (เช่นมีแต่ `SMTP_HOST`) ระบบจะยังอยู่ในโหมดทดลอง (โชว์ OTP บนหน้าจอ) และเตือนในเทอร์มินัลตอนเริ่มระบบ ไม่ปล่อยให้ผู้ใช้ติดค้างโดยไม่ได้รับ OTP

### ขั้นที่ 3: ทดสอบส่งอีเมล
```bash
flask --app wsgi test-email อีเมลที่อยากรับ@gmail.com
```
สำเร็จจะเห็น "ส่งสำเร็จ" และมีอีเมลเข้ากล่องจดหมาย (ถ้าไม่เห็นให้ดูโฟลเดอร์สแปม) ถ้าไม่สำเร็จ คำสั่งจะบอกสาเหตุและวิธีแก้ เช่น รหัสผ่านผิด (ใช้รหัสผ่านปกติแทนรหัสผ่านแอป), ผู้ส่งไม่ตรงกับบัญชี, firewall บล็อกพอร์ต

### ขั้นที่ 4: รันเซิร์ฟเวอร์ใหม่แล้วลองจริง
รัน Backend ใหม่ (`.env` เปลี่ยนแล้วต้องรันใหม่) → เปิดหน้าเว็บ → กด forget password → กรอกอีเมลที่สมัครไว้ → เปิดอีเมลดูรหัส OTP

### ระบบทำงานอย่างไร (ตั้งแต่ตั้งค่าอีเมลแล้ว)
| เรื่อง | พฤติกรรม |
|---|---|
| OTP อยู่ที่ไหน | ส่งทางอีเมลเท่านั้น **ไม่ตอบกลับในคำตอบของ API อีกต่อไป** (หน้าเว็บจะบอกว่า "ส่งแล้ว ให้ตรวจอีเมล") |
| ส่งถึงใคร | อีเมลที่ผูกกับบัญชีนั้นเท่านั้น (ไม่ใช่ที่ผู้ใช้พิมพ์มาเองลอย ๆ) |
| เก็บ OTP | เก็บเฉพาะค่าตีป่น ไม่เก็บรหัสจริงในฐานข้อมูล |
| ขอถี่เกินไป | ขอซ้ำภายใน 60 วินาที ได้ error `TOO_MANY_REQUESTS` (กันถูกใช้ส่งอีเมลถล่ม) ปรับได้ที่ `OTP_RESEND_SECONDS` ใน `config.py` |
| ส่งอีเมลไม่สำเร็จ | ตอบ `EMAIL_SEND_FAILED` (ไม่โชว์รายละเอียดภายใน — ดูสาเหตุจริงใน log ของเซิร์ฟเวอร์) และลบ OTP ที่สร้างไว้ ผู้ใช้กดขอใหม่ได้ทันที |
| ยังไม่ตั้งค่าอีเมล + ไม่ใช่ production | โหมดทดลอง: ตอบ OTP กลับมาแสดงบนหน้าจอ (หน้าเว็บขึ้นป้าย "Dev mode") |
| ยังไม่ตั้งค่าอีเมล + `APP_ENV=production` | ปฏิเสธด้วย `EMAIL_NOT_CONFIGURED` (ไม่รั่ว OTP) |

โค้ดอยู่ที่: `send_email` ส่วนที่ 4 ของ `app/tools.py` (ตัวส่ง SMTP), `request_otp` กับ `otp_email_body` ใน `app/routes/auth.py` (ขั้นตอนและเนื้อหาอีเมล), `test-email` ใน `app/commands.py`

## 7. ลองเรียก API

ทุกเส้นทางขึ้นต้นด้วย `/api/v1` — ยกเว้น `/auth/*` (ส่วนใหญ่) และ `/health` ต้อง**ล็อกอินก่อน** แล้วแนบ token ในหัวคำขอ

```bash
# 0) สมัครสมาชิก (ครั้งแรกครั้งเดียว)
curl -X POST http://127.0.0.1:5000/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"name": "Somchai", "surname": "Jaidee", "email": "somchai@example.com", "password": "abcd1234"}'

# 1) ล็อกอิน → ได้ token
curl -X POST http://127.0.0.1:5000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"identifier": "somchai@example.com", "password": "abcd1234"}'

# 2) เอา token ที่ได้ไปแนบ (แทน <TOKEN>) แล้วขอข้อมูลทั้งหมด
curl http://127.0.0.1:5000/api/v1/snapshot -H "Authorization: Bearer <TOKEN>"

# 3) เพิ่ม stock วัตถุดิบ id 1 อีก 5 ชิ้น (ต้องสร้างวัตถุดิบก่อน: POST /ingredients)
curl -X POST http://127.0.0.1:5000/api/v1/ingredients/1/adjust \
  -H "Authorization: Bearer <TOKEN>" -H "Content-Type: application/json" \
  -d '{"delta": 5}'
```
> บน PowerShell ให้ใช้ `curl.exe` แทน `curl` (เพราะ `curl` ใน PowerShell เป็นคำสั่งอื่น) หรือทดลองด้วยโปรแกรม Postman / Thunder Client ก็ได้

ถ้าผิดกฎ ระบบตอบ error รูปแบบเดียวกันเสมอ:
```json
{"error": {"code": "INSUFFICIENT_STOCK", "message": "Shrimp เหลือไม่พอ (เหลือ 1 pcs)"}}
```

## 8. โครงสร้างโฟลเดอร์

อ่านตามลำดับนี้จะเข้าใจง่ายที่สุด: `models.py` → `routes/stock.py` → `routes/orders.py` → `forecast.py` → `routes/ai.py`
(ทั้งหมดมี Python แค่ **12 ไฟล์** — ไฟล์ยาวถูกแบ่งเป็นหัวข้อใหญ่ ๆ ด้วยแถบคอมเมนต์ `# ====` เปิดดูสารบัญที่ docstring บนสุดของแต่ละไฟล์ก่อนได้)

```
Backend/
├─ wsgi.py               จุดเริ่มรันแอป
├─ requirements.txt      รายการไลบรารีที่ต้องติดตั้ง
├─ .env.example          ตัวอย่างไฟล์ตั้งค่า (คัดลอกเป็น .env — ห้ามใส่ความลับในไฟล์นี้)
├─ .env                  ไฟล์ตั้งค่าจริงของคุณ (ไม่ขึ้น git)
│
├─ app/
│  ├─ __init__.py        create_app() — ประกอบแอปทุกส่วนเข้าด้วยกัน (+ ประกาศ db, cors)
│  ├─ config.py          ค่าตั้งต้น (อ่านจาก .env): ฐานข้อมูล, อายุ token, อายุ OTP, Groq
│  ├─ models.py          ★ ตารางทั้งหมด (1 คลาส = 1 ตาราง) อยู่ไฟล์เดียว
│  ├─ tools.py           เครื่องมือเล็ก ๆ 4 ส่วน: (1) ApiError (2) ตัวช่วยอ่านคำขอ/หาข้อมูลของสาขาตัวเอง
│  │                     (3) ความปลอดภัย: ตีป่นรหัสผ่าน, token, OTP, check_login (4) send_email (SMTP)
│  ├─ commands.py        คำสั่ง flask check-db / init-db / reset-db / test-email
│  ├─ forecast.py        ฝั่ง "โค้ด" ของ AI: เตรียมข้อมูล ตรวจคำตอบ คำนวณแผนความสด (ของค้างคืนน้อยที่สุด)
│  ├─ prompts.py         ข้อความสั่ง AI (system prompt) — แก้นิสัย/รูปแบบคำตอบของ AI ที่นี่
│  └─ routes/            ★ เส้นทาง API — 1 ไฟล์ = 1 กลุ่มงาน
│      ├─ __init__.py    รวมทุกกลุ่ม + ตรวจระบบ (GET /health)
│      ├─ auth.py        สมัคร / ล็อกอิน / ลืมรหัสผ่าน (ส่ง OTP ทางอีเมล)
│      ├─ stock.py       วัตถุดิบ + ประวัติ stock + เมนูและสูตร
│      ├─ orders.py      ออเดอร์ (ตัด/คืน stock) + ตัวเลขสรุปหน้าแรก (dashboard)
│      ├─ notifications.py  ระบบแจ้งเตือน (กระดิ่ง) — API + ฟังก์ชันสร้างแจ้งเตือนที่ไฟล์อื่นเรียกใช้
│      ├─ closing.py     ปิดร้าน: นับของจริง + ของเสีย (วัดว่าของค้างคืนน้อยจริงไหม)
│      └─ ai.py          ให้ AI พยากรณ์พรุ่งนี้ (รวมตัวเรียก Groq) + ความแม่นย้อนหลัง + ความเห็นต่อคำแนะนำ
│
└─ instance/             ไฟล์ฐานข้อมูล SQLite ในเครื่อง (ไม่ขึ้น git)
```

ทิศทางของข้อมูลในหนึ่งคำขอ:
```
หน้าเว็บ ──HTTP──▶ routes/xxx.py ──▶ models.py ──▶ ฐานข้อมูล
                   (ตรวจข้อมูล + ทำงาน + ตอบกลับ)          └─(ai.py)──▶ Groq
```

## 10. แนวคิดสำคัญที่ควรเข้าใจ

| เรื่อง | อธิบายสั้น ๆ | อยู่ที่ไหน |
|---|---|---|
| **ตีป่น (hash)** | รหัสผ่านและ token ถูกแปลงเป็นข้อความที่ย้อนกลับไม่ได้ก่อนเก็บ ต่อให้ฐานข้อมูลรั่วก็เอาไปล็อกอินไม่ได้ | `tools.py` |
| **token** | ล็อกอินสำเร็จได้ข้อความสุ่มยาว ๆ ไว้แนบทุกคำขอ แทนการส่งรหัสผ่านซ้ำ | `tools.py`, `routes/auth.py` |
| **`check_login`** | ฟังก์ชันเดียวที่ทำงาน "ก่อนทุกคำขอ" ตรวจ token แล้วจดว่าผู้ใช้คือใคร อยู่สาขาไหน (`g.user`, `g.branch_id`) ทุกเส้นทางต้องล็อกอิน ยกเว้นรายการ `PUBLIC_PATHS` — เพิ่มเส้นทางใหม่แล้วจึงปลอดภัยโดยอัตโนมัติ | `tools.py` |
| **แยกสาขา** | ข้อมูลทุกอย่างผูกกับสาขา ผู้ใช้เห็น/แก้ได้เฉพาะของสาขาตัวเอง | `tools.find_mine` |
| **commit ครั้งเดียว** | แก้หลายอย่างแล้ว `commit` ทีเดียวท้ายสุด ถ้าผิดกลางทางทุกอย่างถูกยกเลิก (rollback) stock จึงไม่เพี้ยน | `routes/orders.py` |
| **CHECK / UNIQUE ในตาราง** | กฎเช่น "stock ห้ามติดลบ" ฝังไว้ในฐานข้อมูลด้วย เป็นด่านสุดท้ายกันข้อมูลเสีย | `models.py` |
| **แจ้งเตือน** | Backend จดแจ้งเตือนเองเมื่อเกิดเหตุการณ์ (ดูตารางด้านล่าง) หน้าเว็บถามทุก 30 วินาทีแล้วแสดงที่กระดิ่ง "อ่านแล้ว" เก็บแยกรายผู้ใช้ | `routes/notifications.py` |
| **ราคา ณ ตอนสั่ง** | ออเดอร์เก็บชื่อ/ราคาเมนูไว้เอง แก้ราคาเมนูทีหลังไม่กระทบออเดอร์เก่า | `OrderItem` |
| **ไม่เชื่อคำตอบ AI** | AI อาจตอบผิดรูปแบบหรือเลขไม่ลงล้อ โค้ดตรวจและแก้ก่อนใช้เสมอ | `clean_forecast`, `clean_alerts` ใน `forecast.py` |
| **ของค้างคืนน้อยที่สุด** | เติมเท่าที่ขาดพอดี ส่วนที่เหลือค้างให้โปรโมตเมนูที่ใช้มัน | `build_outlook` ใน `forecast.py` |

### ระบบแจ้งเตือน (กระดิ่งบนหน้าเว็บ)

เมื่อมีเหตุการณ์สำคัญ Backend จดแจ้งเตือน 1 แถวในตาราง `notifications` ให้ **ทุกคนในสาขา** เห็น:

| เหตุการณ์ | ระดับ (สีจุด) | ตัวอย่างข้อความ | กดแล้วไปที่ |
|---|---|---|---|
| วัตถุดิบ **ใกล้หมด** (ลดจนต่ำกว่าเกณฑ์) | warn (เหลือง) | วัตถุดิบใกล้หมด: ไก่ — เหลือ 2 pcs | `/stock/<id>` |
| วัตถุดิบ **วิกฤต** | danger (แดง) | วัตถุดิบวิกฤต: ไก่ — เหลือ 1 pcs ควรเติมด่วน | `/stock/<id>` |
| มีออเดอร์ใหม่ | info (น้ำเงิน) | มีออเดอร์ใหม่ #0163 — ยอดรวม ฿130 (2 รายการ) | `/order` |
| ออเดอร์พร้อมเสิร์ฟ | info | ออเดอร์ #0163 พร้อมเสิร์ฟ | `/order` |
| ออเดอร์ถูกยกเลิก | warn | ออเดอร์ #0163 ถูกยกเลิก — คืน stock ให้แล้ว | `/order` |
| AI วิเคราะห์พรุ่งนี้เสร็จ | info | คาดว่าจะมี 142 ออเดอร์ ช่วงเยอะสุด 12:00–14:00 | `/ai` |

กติกาที่ควรรู้:
- **แจ้งเฉพาะตอน "ข้ามเกณฑ์"** (ปกติ→ใกล้หมด หรือ ใกล้หมด→วิกฤต) ไม่แจ้งซ้ำทุกครั้งที่ลดของที่หมดอยู่แล้ว และไม่แจ้งตอนเติมของ
- เกณฑ์ใกล้หมด/วิกฤตเท่ากับที่หน้าเว็บใช้ (หน่วย pcs: ≤2 ใกล้หมด, ≤1 วิกฤต; หน่วย g/ml คูณ 100) — แก้ที่ `CRITICAL_AT`, `LOW_AT`, `UNIT_SCALE` ใน `routes/notifications.py` **และ** `frontend/src/utils/stockStatus.js` ให้ตรงกัน
- แจ้งเตือนถูกบันทึกใน **การ commit เดียวกับงานหลัก** ถ้างานหลักล้มเหลว (เช่น ออเดอร์สร้างไม่ได้เพราะ stock ไม่พอ) จะไม่มีแจ้งเตือนหลงเหลือ
- **"อ่านแล้ว" แยกรายผู้ใช้** (ตาราง `notification_reads`): คนหนึ่งกดอ่านแล้ว อีกคนในสาขาเดียวกันยังเห็นเป็นยังไม่อ่าน
- เก็บแจ้งเตือน 30 วัน (อันเก่ากว่านั้นถูกลบตอนเปิดรายการ) และ API ส่งให้ 30 อันล่าสุด แต่ตัวเลขบนกระดิ่งนับ "ที่ยังไม่อ่านทั้งหมด"
- ข้อมูลแต่ละสาขาแยกกัน: ผู้ใช้เห็นและกดอ่านได้เฉพาะของสาขาตัวเอง
- เพิ่มประเภทแจ้งเตือนใหม่: เพิ่มชื่อใน `NOTIFICATION_KINDS` (`models.py`) แล้วเรียก `add_notification(...)` ในที่ที่เกิดเหตุการณ์ (วางลงถาดก่อน `commit` ของงานนั้น)

**ตารางใหม่ — ถ้าอัปเดตโค้ดจากเวอร์ชันก่อนหน้า ต้องรัน `flask --app wsgi init-db` อีกครั้ง** (สร้างเฉพาะตารางที่ยังไม่มี ไม่แตะข้อมูลเดิม) แล้วรัน Backend ใหม่ — ระบบแจ้งเตือนเพิ่ม `notifications`, `notification_reads`; ระบบปิดร้านและวัดความแม่นของ AI เพิ่ม `forecast_history`, `closing_counts`, `closing_lines`

### ข้อจำกัดตอนนี้ (ต้องรู้)
- **อีเมล OTP ส่งแบบรอผลในคำขอเดียว (synchronous)** — ผู้ใช้รอประมาณ 1–3 วินาทีตอนกดขอ OTP ถ้าส่งปริมาณมากควรย้ายไปส่งเบื้องหลัง (queue) และ Gmail จำกัดราว 500 ฉบับ/วัน
- **ถ้ายังไม่ตั้งค่าอีเมล ระบบอยู่ในโหมดทดลอง** — ตอบ OTP กลับบนหน้าจอ (ใช้เฉพาะตอนพัฒนา) ก่อนใช้งานจริงต้องตั้งค่าอีเมลและตั้ง `APP_ENV=production`
- **ระบบสำหรับร้านเดียว** ผู้สมัครใหม่เป็นพนักงานรออนุมัติจากเจ้าของร้านที่หน้า Statistics บัญชีรออนุมัติเข้าถึงข้อมูลร้านไม่ได้
- **อัปเกรดตารางที่มีข้อมูลด้วย `python scripts/upgrade_inventory.py --apply`** มี backup ก่อนเปลี่ยน schema; `init-db` ใช้สร้างตารางใหม่ ไม่ใช้ลบตารางเพื่ออัปเกรด
- **AI พยากรณ์ได้ดีเมื่อมีประวัติหลายวัน** — ข้อมูลน้อย (ไม่กี่ออเดอร์) ผลจะคลาดเคลื่อน และการเรียก AI มีโควตา/ค่าใช้จ่ายตามแพ็กเกจของ Groq
- **หน้าเว็บต่อกับ Backend ผ่าน proxy ของ Vite** — คำขอ `/api/...` จากหน้าเว็บ (พอร์ต 5173) ถูกส่งต่อมาที่ Backend พอร์ต 5000 ให้เอง ถ้าเปลี่ยนพอร์ต Backend ให้ตั้ง `VITE_BACKEND_URL` ใน `frontend/.env`

## 11. แก้ปัญหาที่เจอบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| `python` ไม่รู้จัก | ยังไม่ได้ติดตั้ง Python หรือไม่ได้ติ๊ก Add to PATH ลองใช้ `py` แทน `python` |
| PowerShell แจ้ง "running scripts is disabled" ตอนเปิด venv | รันครั้งเดียว: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` หรือใช้ Command Prompt แทน |
| `flask` ไม่รู้จัก / `ModuleNotFoundError` | ยังไม่ได้เปิด venv (ต้องเห็น `(venv)` หน้าบรรทัด) หรือยังไม่ได้ `pip install -r requirements.txt` |
| `Port 5000 is in use` หรือหน้าเว็บได้ error แปลก ๆ | มีเซิร์ฟเวอร์เก่าเปิดค้างที่พอร์ต 5000 (ใช้โค้ด/ฐานข้อมูลเก่า) — ปิดตัวเก่าก่อน หรือใช้พอร์ตอื่น `flask --app wsgi run -p 5001` (แล้วตั้ง `VITE_BACKEND_URL` ใน `frontend/.env`) |
| สมัคร/ล็อกอินได้ error 500 | ยังไม่ได้สร้างตาราง — รัน `flask --app wsgi init-db` แล้วรันเซิร์ฟเวอร์ใหม่ |
| เปิด `/health` ได้ `{"database":"down"}` | เชื่อมฐานข้อมูลไม่ได้ รัน `check-db` ดูสาเหตุ ตรวจ `DATABASE_URL`, รหัสผ่าน, firewall, `DB_SSL_CA` |
| `Access denied for user` (MySQL) | ชื่อผู้ใช้/รหัสผ่านผิด หรือรหัสผ่านมีอักขระพิเศษที่ยังไม่ได้แปลงเป็นรหัส URL |
| `Unknown database` (MySQL) | ยังไม่มีฐานข้อมูลชื่อนั้นในเซิร์ฟเวอร์ (Aiven ใช้ `defaultdb` ได้เลย) |
| ปัญหา SSL / certificate (MySQL) | ตั้ง `DB_SSL_CA` เป็น path ของไฟล์ `ca.pem` ที่ผู้ให้บริการให้ (ใช้ `/`) |
| ตั้ง `DATABASE_URL` แล้วแต่ยังใช้ SQLite | เขียนคอมเมนต์ต่อท้ายบรรทัดเดียวกับค่า ทำให้อ่านเป็นค่าว่าง — ให้ขึ้นบรรทัดใหม่สำหรับคอมเมนต์ แล้วรัน `check-db` ดูว่าต่อกับอะไรอยู่ |
| ข้อความภาษาไทยเป็น `???` ใน MySQL | ฐานข้อมูลควรใช้ utf8mb4 (`check-db` จะแจ้งชุดตัวอักษร) |
| หน้าเว็บเรียก API แล้วติด CORS | ใส่ที่อยู่หน้าเว็บใน `CORS_ORIGINS` ของ `.env` (ค่าเริ่มต้น `http://localhost:5173`) แล้วรันเซิร์ฟเวอร์ใหม่ |
| แก้ `.env` หรือโค้ดแล้วไม่เปลี่ยน | ต้องหยุดแล้วรันเซิร์ฟเวอร์ใหม่ (หรือรันด้วย `--debug`) |
| ล็อกอินไม่ได้ | ฐานข้อมูลเริ่มต้นว่างเปล่า ไม่มีบัญชีทดลอง — สมัครที่หน้า Register ก่อน |
| AI แจ้ง `AI_NOT_CONFIGURED` | ยังไม่ได้ใส่ `GROQ_API_KEY` ใน `.env` (หรือยังไม่ได้รันเซิร์ฟเวอร์ใหม่หลังใส่) |
| AI แจ้ง `Groq ปฏิเสธ API key` (401) | คีย์ผิดหรือถูกลบแล้ว สร้างคีย์ใหม่ที่ console.groq.com/keys |
| AI แจ้ง `Groq ตอบผิดพลาด (404)` | โมเดลที่ตั้งไว้ไม่มีให้ใช้แล้ว ตั้ง `GROQ_MODEL` เป็นโมเดลที่ยังมี (ดู console.groq.com/docs/models) |
| AI แจ้ง `เรียก Groq ถี่เกินกำหนด` (429) | ชนโควตา รอสักครู่แล้วลองใหม่ |
| AI แจ้ง `ยังไม่มีออเดอร์ให้ AI วิเคราะห์` | ต้องมีออเดอร์ในระบบอย่างน้อย 1 ใบ (ไม่นับที่ยกเลิก) |
| ตั้ง `SMTP_HOST` แล้วแต่ยังโชว์ OTP บนหน้าจอ (Dev mode) | ตั้งค่าอีเมลไม่ครบ — ต้องมีทั้ง `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD` (ดูคำเตือนในเทอร์มินัลตอนรัน Backend) |
| ขอ OTP แล้วอีเมลไม่มา | ดูโฟลเดอร์สแปม, รัน `flask --app wsgi test-email อีเมลคุณ` ดูสาเหตุ, ตรวจว่าตั้งค่า `SMTP_*` ใน `.env` แล้วและรันเซิร์ฟเวอร์ใหม่ |
| `test-email` แจ้ง SMTPAuthenticationError | ใช้รหัสผ่านปกติของ Gmail ไม่ได้ — ต้องเปิดการยืนยัน 2 ขั้นตอนแล้วสร้าง "รหัสผ่านแอป" (ข้อ 5) |
| `test-email` แจ้งหมดเวลา / ต่อไม่ได้ | เครือข่ายอาจบล็อกพอร์ต 587/465 ลองเปลี่ยนเครือข่าย หรือสลับระหว่าง `587` กับ `465` |
| ขอ OTP ได้ `TOO_MANY_REQUESTS` | ขอถี่เกินไป รอ 60 วินาทีแล้วลองใหม่ (ปรับได้ที่ `OTP_RESEND_SECONDS`) |
| ขอ OTP ได้ `EMAIL_NOT_CONFIGURED` | `APP_ENV=production` แต่ยังไม่ได้ตั้งค่า `SMTP_*` |
| กระดิ่งไม่ขึ้นแจ้งเตือน / ได้ error ตอนเปิดรายการแจ้งเตือน | ยังไม่ได้สร้างตารางใหม่ — รัน `flask --app wsgi init-db` แล้วรัน Backend ใหม่ |
| อยากล้างข้อมูลทั้งหมด | รัน `flask --app wsgi reset-db` |
